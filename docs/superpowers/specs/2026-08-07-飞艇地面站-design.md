# 灵云01号 飞艇地面站（Qt6）设计文档

> 日期：2026-08-07
> 状态：已获用户认可
> 面向：地面站（Qt6 桌面端）开发者

---

## 1. 目标与范围

开发一个 **Qt6 桌面地面站**，用于本地监控飞艇各分系统的运行情况与参数。

- **输入链路**：串口数传（遵循《地面站对接协议》），机载树莓派 5 将 BMS / MPPT / DCDC 设备状态聚合为单行 JSON，加帧头帧尾（`0xAA 0x55` + JSON + `\n`），以 115200 8N1 周期 5Hz 下传。
- **链路性质**：机载 → 地面单向，**纯监控**，当前阶段**不含控制指令下发**。
- **本地不安装 ROS2**：ROS2 是机载端的采集手段，下传走串口，地面站只需串口 + JSON 解析。

### 明确不做的（YAGNI / 范围外）

- 不实现控制指令下发（协议当前单向下传）。
- 不做 4G 上云 / MQTT 远程链路（属另一文档范畴，可后续扩展）。
- 不实现完整的飞控 / 位置 / 姿态监控（预留扩展，本阶段不落地）。

## 3. 技术栈

| 模块 | 选型 | 说明 |
| --- | --- | --- |
| 串口 | `QSerialPort`（Qt 官方） | 跨平台，非阻塞事件驱动 |
| JSON | `QJsonDocument`（Qt 官方） | 解析协议帧 |
| 曲线 | `QCustomPlot`（第三方） | 实时曲线，交互丰富 |
| 记录 | CSV 文件 | 简单、可回放、Excel 可读 |
| 配置 | `QSettings`（Qt 官方） | 串口参数、界面设置持久化 |
| 构建 | CMake + Qt6 | 跨平台 |

> ⚠️ **许可注意**：QCustomPlot 采用 GPL 或商业双许可。地面站若为内部自用监控（非分发）GPL 可接受；若需闭源商用分发需购买商业许可。当前按内部监控规划。

## 4. 架构分层与模块

```
┌────────────────── UI 层 (Qt Widgets) ──────────────────┐
│ MainWindow │ StatusBar │ DevicePanel(BMS/MPPT/DCDC)    │
│ ChartWidget │ AlarmPanel │ LogPanel │ ReplayPanel      │
└──────────────────────┬─────────────────────────────────┘
                       │ 信号槽（仅依赖 Core 层接口）
┌────────────────── Core 层 ─────────────────────────────┐
│ DataBus │ AlarmEngine │ Recorder(CSV) │ ReplayEngine    │
│ ConfigManager(QSettings)                                │
└──────────────────────┬─────────────────────────────────┘
┌────────────────── Model 层 ────────────────────────────┐
│ TelemetryData { t, Bms, Mppt, Dcdc }（预留扩展）         │
└──────────────────────┬─────────────────────────────────┘
┌────────────────── Comms 层 ────────────────────────────┐
│ SerialManager: QSerialPort + 帧解析 + QJson 解码        │
└─────────────────────────────────────────────────────────┘
```

### 4.1 Comms 层

**SerialManager**
- 职责：打开/关闭/配置串口；缓冲字节流，按 `0xAA 0x55` 定位帧头、至 `\n` 截取 JSON；QJson 解析为 `TelemetryData`。
- 输出：`signal telemetryReceived(const TelemetryData&)`。
- 所有协议细节（分帧、字段映射、离线判定）隔离在此层，未来换 ROS2/网络链路只需替换本层。

### 4.2 Model 层

强类型数据结构，字段与协议文档一一对应：

- `TelemetryData { double t; std::optional<Bms> bms; std::optional<Mppt> mppt; std::optional<Dcdc> dcdc; }`
- `Bms { online, pack_v, pack_i, soc, max_v, min_v, diff_v, max_t, alarm }`
- `Mppt { online, pv_v, pv_p, batt_v, charge_i, today, total, fault }`
- `Dcdc { online, in_v, out_v, out_i, out_p, temp, enabled, fault }`

`std::optional` 表示设备离线/未出现在帧中（与协议"离线设备不出现在帧中"对应）。预留扩展：未来新增设备类型直接追加字段，不破坏现有结构。

### 4.3 Core 层

- **DataBus**：接收 `telemetryReceived`，向订阅方（UI 刷新、AlarmEngine、Recorder）分发。解耦生产与消费。
- **AlarmEngine**：判定告警条件——
  - 设备超时（默认 3s，`link_timeout_s`）离线 → 离线告警；
  - `bms.alarm` 非 0（1 故障 / 2 严重）；
  - `mppt.fault` / `dcdc.fault` 非 0；
  - （预留）自定义阈值。
  - 输出：`signal alarmTriggered(id, level, msg)` / `alarmCleared(id)`。
- **Recorder**：把 `TelemetryData` 追加写入 CSV（时间戳 + 各字段），带自动分片/写失败容错。
- **ReplayEngine**：读取录制 CSV，按时间戳以真实节奏重放，驱动同一套 UI。
- **ConfigManager**：`QSettings` 保存串口设备、波特率、所选曲线参数、窗口几何等。

### 4.4 UI 层

只订阅数据并刷新，不直接接触协议。

## 5. 数据流与线程模型

- 5Hz、每帧 <2KB，数据量极小。采用 **Qt 单线程事件循环**（QSerialPort 非阻塞，`readyRead` 信号驱动），无需额外线程，简单可靠。
- 数据流：
  `QSerialPort.readyRead → SerialManager 分帧/解析 → TelemetryData → DataBus → {UI 刷新, AlarmEngine, Recorder}`
- 所有接口按信号隔离，若未来数据量增大可平滑迁移到工作线程。

## 6. 界面布局（总览仪表盘式）

- **顶部 StatusBar**：链路状态灯、BMS/MPPT/DCDC 在线灯、当前时间 / 运行时长。
- **中部 DevicePanel**：BMS / MPPT / DCDC 三张卡片，数值 + 状态色（正常绿 / 告警黄 / 故障红），离线置灰。
- **底部 Tab**：
  - `实时曲线`：QCustomPlot，可选择要显示的参数；
  - `告警`：告警事件列表；
  - `日志`：链路/操作日志；
  - `回放`：选择 CSV 文件回放。

## 7. 错误处理与鲁棒性

| 场景 | 处理 |
| --- | --- |
| 串口打开失败 | 明确报错，列出可选设备与波特率 |
| 帧解析 / JSON 失败 | 丢弃本帧，继续找下一帧头，不影响链路 |
| 设备超时(3s)离线 | 状态灯置灰，AlarmEngine 触发离线告警 |
| 记录写入失败 | 日志告警，不崩溃 |
| 回放无文件 / 格式错 | 提示并安全返回 |

---

## 8. 测试策略

- **协议单测**：`FrameParser` / `JsonDecoder` 单元测试，覆盖正常帧、坏帧、字段缺失、设备离线。
- **链路模拟**：用 `socat`/pty 虚拟串口 + 脚本按协议发送数据，端到端验证显示与告警。
- **回放自测**：录制 CSV 直接回放验证显示一致性。
- 复用仓库 `tools/` 已有模拟器思路。

---

## 9. 里程碑（建议拆分）

1. **M1 通信与解析**：SerialManager + Model + 单测，串口收到数据能正确解析打印。
2. **M2 核心监控**：DataBus + StatusBar + DevicePanel，实时显示三设备。
3. **M3 扩展功能**：AlarmEngine + Recorder + ReplayEngine + ConfigManager。
4. **M4 曲线与收尾**：ChartWidget 实时曲线 + 界面打磨 + 跨平台构建脚本。

每个里程碑可独立验收，先跑通 M1 再做 M2，降低风险。

---

## 10. 关键风险

- **QCustomPlot 许可**：需按发布方式确认 GPL/商业许可。
- **串口枚举跨平台差异**：Linux `/dev/ttyUSB*` 与 Windows `COM*` 枚举方式不同，需封装统一接口。
- **协议变更**：机载字段可能演进，Model 与 SerialManager 需易扩展、易回归测试。
