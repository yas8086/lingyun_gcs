# 修复记录：启动最大化时标题栏按钮状态错误

> 日期：2026-08-27
> 环境：X11 + GNOME（Mutter 窗口管理器，mutter-x11-frames 服务端标题栏）
> 涉及文件：`src/qml/main.cpp`（启动流程）、`src/qml/main.qml`（窗口属性）

## 一、问题现象

软件启动即全屏铺满，但标题栏右上角中间按钮显示"最大化"（单方框）图标，而非"还原"（两叠方框）；点击该按钮后窗口大小不变，按钮才变成"还原"。

关键观察（用户发现，定位根因的决定性线索）：**启动首帧窗口左上/右上角带圆角，点击最大化后才变直角贴边**——圆角是 Mutter 对 Normal 态窗口的装饰，说明启动时的窗口实际是 **Normal 状态、几何恰好铺满屏幕的大窗**，从未真正进入最大化状态；按钮显示"最大化"图标是 WM 的诚实反馈。

## 二、根因分析

1. **双通道状态竞争**（早期）：QML `visibility: Window.Maximized` 在 `engine.load()` 时即向 WM 请求一次最大化；随后 C++ 又 `setWindowState(Maximized) + show()`。两次乱序请求导致 WM 状态位与按钮图标错序。
2. **Mutter 吞掉早期状态请求**（核心）：即使合并为 C++ 单一路径，在 X11 上：
   - `show()` 之前 `setWindowState(Maximized)` —— map 前预置的状态被 Mutter 忽略；
   - `show()` 后同步连发 `NoState → Maximized` —— 仍处于 map/reparent 事务未完成的窗口期，消息被吞或错序；
   - `QTimer::singleShot(0, …)` —— 事件循环第一拍触发，X server 的 map 通知尚未走完、WM 尚未注册完窗口，请求同样被静默吞掉。
   三种尝试的表现一致：窗口以 Normal 大窗出现（带圆角），按钮停留"最大化"。

## 三、最终方案（已验证）

`main.cpp` 启动流程改为"铺满几何 + 延迟 100ms 最大化"两段式：

```cpp
// ① 铺满可用区：Normal 态窗口几何即全屏，防首帧闪现小窗，
//    后续最大化瞬间只有圆角消失，无大小跳变
win->setGeometry(win->screen()->availableGeometry());
win->show();
// ② 事件循环启动且窗口被 WM 完全注册后再请求最大化——
//    与用户手点标题栏按钮走完全相同的 _NET_WM_STATE 消息路径，
//    Mutter 必然响应：最大化生效 + 按钮同步为"还原"
QTimer::singleShot(100, win, [win] { win->setWindowState(Qt::WindowMaximized); });
```

同时 QML 侧保持 `visible: false`，由 C++ `show()` 统一控制窗口显示，彻底移除 `visibility: Window.Maximized`，避免双通道竞争。

## 五、遗留说明

- `setGeometry(铺满)` 依赖 `QScreen::availableGeometry()`，多屏下取主屏可用区；窗口 show 后由 WM 最大化接管，换分辨率自适应。
- 100ms 延迟窗口内界面已是全屏大小，用户视觉无感知（仅圆角在 0.1s 后消失）。
- 若日后更换 WM/桌面（如 KDE/KWin 或 Wayland 会话），此两段式方案依然适用（延迟请求对任何 WM 都是合法路径）；Wayland 下 Qt 走 xdg_toplevel.set_maximized，机制不同但同样在 mapped 后请求最稳。
